Keep every user on the latest version.

A small, typed wrapper around Google Play In-App Updates on Android and an App Store version check on iOS. Add one hook to your root component and users are asked to update whenever a newer version is out.

$ npm install @nameisjayant/react-native-in-app-update
License MIT Android Play Core app-update 2.1.0 iOS StoreKit Web safe no-op

Features

Everything you need to ship updates, nothing you have to configure.

Mandatory by default

Shows the update screen on app open and on every return to the foreground, and again if the user backs out.

Flexible updates

Downloads in the background with progress, so you can show your own “Restart to update” prompt.

One hook

useInAppUpdate() checks, prompts, resumes interrupted updates and installs.

iOS too

Checks the App Store for a newer version and shows the App Store page inside your app. No API keys.

Imperative API

Full control with checkForUpdate, startUpdate, completeUpdate and an install-state listener.

Safe everywhere

Built as a TurboModule for the New Architecture. On web it reports unsupported, so one codebase runs anywhere.

Quick start

Call the hook once in your root component.

App.tsx
import { useInAppUpdate } from '@nameisjayant/react-native-in-app-update';

export default function App() {
  useInAppUpdate({ enabled: !__DEV__ });

  return <RootNavigator />;
}

That's all. When a new version is on Play or the App Store, users see the update screen and can't continue until they update.

Tip: enabled: !__DEV__ turns the hook off in debug builds. Builds installed from Android Studio or yarn android aren't from Play, so they can't receive updates.

How it works

Same hook, native behaviour on each platform.

Android · Google Play

  1. Check Play's In-App Updates API for a newer versionCode.
  2. Prompt with Play's full-screen immediate update (or a flexible background download).
  3. Install and restart. Interrupted updates are resumed automatically.

iOS · App Store

  1. Look up your bundle ID with Apple's iTunes Lookup API (device region, then US).
  2. Compare the store version with CFBundleShortVersionString.
  3. Show your App Store page inside the app (SKStoreProductViewController), falling back to the App Store app.

Status lifecycle

The hook's status moves through these states:

idle→ checking→ prompting→ downloading→ downloaded→ installing

Branches: up_to_date when there's nothing new, canceled when the user dismisses (re-prompted when mandatory), error on failure, unsupported on web.

Usage

Mandatory update (default)

tsx
useInAppUpdate(); // same as useInAppUpdate({ mandatory: true })

How it behaves on Android:

SituationBehaviour
App opened or resumed, update availableShows Play's full-screen immediate update
User backs out of the update screenShows it again right away (or on next resume)
Immediate update was interruptedResumes it
Play doesn't allow an immediate updateDownloads it as a flexible update and installs it automatically when done

No update, or not installed from PlayDoes nothing (status is up_to_date or error)

Flexible update

Let users keep using the app while the update downloads, then ask them to restart.

UpdateBanner.tsx
import { useInAppUpdate } from '@nameisjayant/react-native-in-app-update';

function UpdateBanner() {
  const { status, progress, completeUpdate } = useInAppUpdate({
    mandatory: false,
  });

  if (status === 'downloading') {
    return <Text>Downloading update… {Math.round(progress * 100)}%</Text>;
  }

  if (status === 'downloaded') {
    return (
      <Snackbar
        text="An update has been downloaded"
        action="Restart"
        onPress={completeUpdate} // installs and restarts the app
      />
    );
  }

  return null;
}

Imperative API

Decide yourself when and how to update, for example only for high-priority releases.

ts
import {
  checkForUpdate,
  startUpdate,
  completeUpdate,
  addInstallStateListener,
} from '@nameisjayant/react-native-in-app-update';

const info = await checkForUpdate();

if (info.updateAvailability === 'available' && info.updatePriority >= 4) {
  if (info.isImmediateAllowed) {
    const result = await startUpdate('immediate'); // 'accepted' | 'canceled' | 'failed'
  }
}

// Track a flexible download
const sub = addInstallStateListener((state) => {
  console.log(state.installStatus, state.bytesDownloaded, state.totalBytesToDownload);
  if (state.installStatus === 'downloaded') completeUpdate();
});

// later
sub.remove();

iOS behaviour

iOS has no equivalent of Play's in-app updates, so the library does what most iOS apps do: compare against the App Store and show your store page in-app. The same hook works unchanged.

Situationmandatory: truemandatory: false
Update available on open/resumeShows the App Store pageShows the App Store page
User closes the pageShows it again right awaystatus becomes canceled, app continues
User taps UpdateiOS installs it and relaunches the appSame
Device iOS older than the new version's minimumTreated as no updateSame

Differences from Android

  • availableVersion and releaseNotes are filled in. availableVersionCode and updatePriority are always 0.
  • clientVersionStalenessDays is days since the App Store release, so you can force an update after a grace period.
  • startUpdate() always resolves 'canceled' once the page closes. Apple doesn't tell apps whether the user updated.
  • type, completeUpdate() and addInstallStateListener() don't apply. They're accepted and do nothing.
  • Apple's lookup can lag a few hours behind a new release.

Types

types.ts
type UpdateType = 'immediate' | 'flexible';

type UpdateFlowResult = 'accepted' | 'canceled' | 'failed'; // always 'canceled' on iOS

type UpdateInfo = {
  updateAvailability: 'unknown' | 'not_available' | 'available' | 'in_progress' | 'unsupported';
  installStatus: InstallStatus;
  availableVersionCode: number;              // Play versionCode, 0 on iOS
  availableVersion: string | null;           // App Store version, null on Android
  releaseNotes: string | null;               // App Store "What's New", null on Android
  isImmediateAllowed: boolean;
  isFlexibleAllowed: boolean;
  clientVersionStalenessDays: number | null; // days since Play learned about / App Store released it
  updatePriority: number;                    // 0–5, set via the Play Developer API, 0 on iOS
  bytesDownloaded: number;
  totalBytesToDownload: number;
};

type InstallState = {
  installStatus: InstallStatus;
  installErrorCode: number; // Play InstallErrorCode, 0 = no error
  bytesDownloaded: number;
  totalBytesToDownload: number;
};

type InstallStatus =
  | 'unknown' | 'pending' | 'downloading' | 'downloaded'
  | 'installing' | 'installed' | 'failed' | 'canceled' | 'requires_ui_intent';

All types are exported from the package:

ts
import type { UpdateInfo, UpdateStatus, UseInAppUpdateOptions } from '@nameisjayant/react-native-in-app-update';

iOSApp Store version check + in-app App Store page

Testing in-app updates

In-app updates only work for an app installed from Google Play. Use internal app sharing to test without publishing.

  1. Set up. In Play Console, enable internal app sharing and add your Google account as a tester. On the device, open Play Store → Settings → About, tap Play Store version 7 times, then turn on Internal app sharing.
  2. Install v1. Build a release APK/AAB with versionCode 1, upload it to internal app sharing, open the link on the device and install it.
  3. Publish v2. Bump to versionCode 2, build and upload again. Open the new link but don't tap Update. Just let Play see it.
  4. Try it. Open the app from step 2. The Play update screen appears; press back and it appears again.

The check uses your app's live App Store listing, so there's nothing to upload.

  1. Set the app's bundle ID to one that's live on the App Store.
  2. Set its Version (CFBundleShortVersionString) lower than the App Store version, e.g. 0.0.1.
  3. Run it on a device or simulator. The App Store page appears; close it and it appears again.

On the simulator the App Store page may not load (there's no App Store app), so test on a real device for the full flow.

The example/ app shows the current status and version info, with a Mandatory / Flexible switch.

Troubleshooting

ProblemCause / fix
Install Error(-10): The app is not owned by any user on this deviceThe app wasn't installed from Play (e.g. yarn android). Expected in dev. The hook reports status: 'error' and the app keeps working. Use enabled: !__DEV__.
Update screen never showsMake sure the installed versionCode is lower than the one on Play, and open the Play Store listing once so Play's cache refreshes.
status is unsupportedYou're on web or another platform without in-app updates.
iOS: up_to_date though a new version is liveApple's lookup can lag a few hours. Also check the bundle ID matches the App Store app and the device meets the new version's minimum iOS.
iOS: E_NOT_AVAILABLE from startUpdate()No newer App Store version for this device. Call checkForUpdate() first.
